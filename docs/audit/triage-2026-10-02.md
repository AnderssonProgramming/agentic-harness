## Observation outside the criteria (not counted)

The baseline and run B both noted that **provider error bodies travel to the browser** in the `error` event's `message` (`server/llm/handler.ts`) and are kept in the stored conversation. They aren't rendered, so ERR-01 is met, but they're visible in DevTools and in localStorage. It's recorded as debt **D-03**, with a proposed new criterion for the next audit cycle. The criteria don't change between the before and after runs, so the comparison holds.

## Addendum: a defect found by the fix pass's property test (2026-10-02)

| Finding                                                                             | Criterion | PO risk  | Decision                       |
| ----------------------------------------------------------------------------------- | --------- | -------- | ------------------------------ |
| **P-01**: an oversized request poisons the connection, and long conversations break | ERR-02    | **High** | **Fix** (contract Amendment 2) |

**What:**

1. When a request body is over `maxRequestBytes` (256,000), `readJsonBody` (`server/llm/handler.ts:31-46`) throws without draining or closing the upload. The leftover bytes stay on the keep-alive connection, so **the next request on that connection hangs**. That's deterministic, with an exact reproduction in the subagent's report.
2. **The browser sends the whole conversation with every message.** The server trims what reaches the model, but not what the browser sends. So once a conversation passes about 256 KB of text, every send is rejected, and following requests can hang. **Long conversations stop working**, which violates ERR-02's "no failure leaves the app unusable".

**Why the audit missed it:** the criteria checked that a malformed request gets an error (IN-01) and that failures don't make the app unusable (ERR-02), through the `verify:*` scripts. None of those scripts sends more than one oversized request, or grows a conversation past 256 KB. A property-style test over many request shapes found it. Recorded as a lesson for the criteria in TECH-DEBT.md D-04.
