## Reliability test conditions

| Run | Condition                                                           | Invocation                                                                           |
| --- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 1   | Simple, one word, all defaults                                      | `/new-route knowledge`                                                               |
| 2   | Multi-word name, custom path and title                              | `/new-route team-conventions /conventions "Team conventions"`                        |
| 3   | Natural language, no slash command (tests the description triggers) | "Add a screen for B-06 where new hires will browse the team's onboarding documents." |
| –   | Negative: conflict                                                  | `/new-route chat /` (path already exists). Must stop and change nothing              |

Each run is a fresh headless `claude -p` session in its own clean clone with `npm ci`, so no run can lean on the previous one. The generated routes stay in the clones: they are evidence, not product. Nothing lands on `main` without a backlog item.

### Change to the conditions after the first series

The first series' run 3 used "Add a settings screen where the user will pick the inference engine." The agent correctly refused: a UI to pick the engine contradicts ADR-03 and B-04. That's a bad test prompt, not a skill failure, so run 3 now uses a request that traces to a backlog item (B-06). Every run is invoked with `--allowedTools "Skill(new-route)"`, the headless equivalent of approving the skill once (see the skill's known errors). Details are in `docs/evidence/skill-new-route-reliability.md`.

## Dependencies

None. The router, the generator and the browser check use only React, Node built-ins and the already-approved Vite.
